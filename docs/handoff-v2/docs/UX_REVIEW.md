# Usability review: apply principles selectively

The owner supplied a list of 20 UX principles for consideration. These are **decision aids**, not instructions to add 20 effects or redesign the V2 experience. The reference is the design baseline; assess whether the implementation respects the principles without removing its warmth or interactivity.

| Principle | Practical V2 review question |
| --- | --- |
| Aesthetic-usability | Is the warm visual presentation polished while labels/actions remain usable? |
| Hick's law | Are navigation and gallery/filter choices constrained to understandable options? |
| Fitts's law | Are menu links, cards, quiz answers, CTAs and modal close controls comfortable to tap? |
| Jakob's law | Do menus, carousels, forms, video controls and back actions follow familiar web conventions? |
| Miller's law | Are options chunked by section and not overloaded onto one screen? |
| Doherty threshold | Does tap/click feedback feel prompt; are heavier images/video deferred until needed? |
| Proximity | Are labels adjacent to their respective inputs, photos and actions? |
| Similarity | Do cards and buttons with equivalent meanings use consistent patterns? |
| Common region | Do gallery cards, quiz and enquiry steps have clear visual boundaries? |
| Visual hierarchy | Can a new parent quickly identify academy, mentor, offer and primary action? |
| Progressive disclosure | Does the four-step enquiry reveal one useful question at a time? |
| Recognition over recall | Are grade/level controls visible, with selected states and intuitive labels? |
| Von Restorff effect | Does the primary parent CTA stand out without making every element equally loud? |
| Peak-end rule | Does the end of the parent experience feel helpful and reassuring? |
| Goal-gradient | Is step progress visible, but not manipulative, during enquiry and quiz? |
| Serial position | Are important contact/location details easy to find early and late in the page? |
| Tesler's law | Is the interaction straightforward without burdening parents with unnecessary details? |
| Postel's law | Are form responses resilient to reasonable input variations once a real form is approved? |
| Occam's razor | Are animations/components serving the story, or creating needless complexity? |
| Feedback loops | Are selections, answers and navigation actions visibly acknowledged? |

## Higher-priority quality gates

- **Accessibility:** keyboard-only use, visible focus states, meaningful text alternatives, adequate contrast, motion preferences, correct label/role relationships.
- **Mobile usability:** no horizontal overflow, readable headlines, reachable controls, media modal that fits the viewport, useful sticky/navigation behavior.
- **Performance:** responsive images, lazy-loaded offscreen photos, restrained video preload, usable slow-connection experience, no large shifts while loading.
- **Honest persuasion:** use genuine community/student moments with consent; no invented proof, fear-based promises or misleading endorsements.

Record any new UI changes under the parity report. Improvements for accessibility and content truthfulness are welcome; visual redesigns require owner review.
